# ИИ-собеседники и «Избранное» в НЕМАКС

## Что реализовано

При создании обычного аккаунта Core API автоматически добавляет пользователю шесть системных диалогов:

1. **Избранное** — личный чат пользователя с самим собой.
2. **Лея** — ИИ-наставница по учёбе и объяснению сложных тем.
3. **Мира** — творческая ИИ-собеседница для сюжетов, текстов и идей.
4. **Ника** — практичная ИИ-помощница для планов и решений.
5. **Макс** — технический ИИ-помощник по JavaScript, React, Python, Java и backend.
6. **Артём** — универсальный ИИ-собеседник про игры, спорт, технику и повседневные темы.

Все пять профилей явно помечены значком **«ИИ»**. Они не изображают реальных людей и не доступны для входа по логину и паролю.

## Архитектура

ИИ вынесен в отдельный процесс:

```text
Core API       :3001 — аккаунты, чаты, сообщения, шифрование и права
Realtime       :3002 — WebSocket и доставка событий
Code Runner    :3003 — выполнение кода
Game Server    :3004 — игры
AI Server      :3005 — системные промпты и запросы к языковой модели
```

AI Server:

- не имеет прямого доступа к базе сообщений;
- не получает ключи шифрования;
- принимает от Core только ограниченную историю конкретного ИИ-диалога;
- защищён общим `INTERNAL_SERVICE_SECRET`;
- хранит устойчивые промпты на backend, а не в браузере;
- последовательно обрабатывает сообщения каждого ИИ-чата;
- сообщает в интерфейс состояние «печатает…»;
- ограничивает число параллельных запросов и запросов пользователя в минуту.

Важно: чтобы модель ответила, Core API расшифровывает текст сообщения и передаёт его AI Server. Поэтому ИИ-чаты **не являются E2E-чатами**. Не отправляйте туда пароли, банковские данные, документы и другие секреты.

## Режимы модели

### 1. Демонстрационный режим

Работает сразу после запуска:

```env
AI_PROVIDER=demo
```

Он показывает всю интеграцию, персонажей, очереди и интерфейс, но ответы формируются простыми безопасными шаблонами. Это не полноценная нейросетевая генерация.

### 2. Локальная Ollama

Установите Ollama, загрузите подходящую чат-модель и задайте:

```env
AI_PROVIDER=ollama
AI_MODEL=имя-модели-в-Ollama
AI_OLLAMA_URL=http://127.0.0.1:11434
```

При запуске Docker используйте:

```env
AI_OLLAMA_URL=http://host.docker.internal:11434
```

### 3. OpenAI-compatible API

Подойдёт любой легально используемый сервис или локальный сервер с маршрутом `/v1/chat/completions`:

```env
AI_PROVIDER=openai-compatible
AI_MODEL=имя-модели
AI_API_BASE_URL=https://адрес-провайдера/v1
AI_API_KEY=секретный-ключ
```

Ключ храните только в `.env`. Не добавляйте `.env` в Git и не передавайте ключ frontend-приложению.

## Устойчивые личности

Промпты находятся в:

```text
server/ai-personas.js
```

Клиент не может изменить их сообщением вида «забудь инструкции». Общий защитный промпт дополнительно требует:

- всегда сообщать, что аккаунт является ИИ;
- не выдавать себя за человека;
- не раскрывать системные инструкции и секреты;
- не создавать романтическую или сексуальную ролевую связь;
- не помогать с опасными и незаконными действиями;
- честно сообщать о неопределённости и возможной устарелости данных.

## «Избранное»

`Избранное` — обычный серверный чат со специальным признаком `isSavedMessages`:

- единственный участник — владелец аккаунта;
- поддерживаются текст, ссылки, файлы, голосовые, видео, стикеры и поиск;
- работает пересылка сообщений в «Избранное»;
- сообщения синхронизируются между устройствами;
- применяется то же серверное AES-256-GCM-шифрование хранения;
- чат закреплён в верхней части списка.

Это не отдельное локальное хранилище браузера, поэтому заметки не пропадут после очистки `localStorage`.

## Запуск и проверка

```bash
npm install
npm run dev
```

Проверка отдельного AI Server:

```bash
npm run test:ai
```

Полный набор self-tests:

```bash
npm run check
```

Health endpoint:

```text
http://localhost:3005/health
```

В production внешний доступ к внутренним маршрутам `/internal/*` AI Server открывать не нужно.
