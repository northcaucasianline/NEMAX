# Безопасность

## Авторизация

- уникальный логин и пароль, без телефона и электронной почты;
- пароль хешируется `scrypt` с уникальной солью;
- access-токены короткоживущие;
- refresh-токены меняются при каждом обновлении;
- в базе хранятся SHA-256-хеши токенов, а не их открытые значения;
- предусмотрены отзыв сессий, rate limiting, TOTP и журнал активных устройств.

## Серверное шифрование

Сообщения и вложения шифруются AES-256-GCM. Ключ создаётся CSPRNG и меняется каждые пять минут. Для каждой операции используется отдельный случайный IV и GCM-тег целостности. Старые ключи сохраняются для чтения истории.

Это защищает резервные копии и данные на диске, но Core способен расшифровывать их.

## Секретный режим

В секретном режиме текст шифруется в браузере случайным AES-GCM-ключом. Ключ сообщения оборачивается отдельно для зарегистрированных устройств через ECDH. Core хранит шифротекст и envelopes, но не открытый текст.

Ограничение: реализация не проходила независимый криптографический аудит и пока не включает полный Double Ratchet, key transparency и MLS для больших групп. Не используйте её как замену аудированным протоколам в высокорисковых сценариях.

## Production checklist

- установить HTTPS/WSS;
- заменить все секреты из `.env.example`;
- закрыть Core/Realtime внутренней сетью;
- хранить секреты в Vault/KMS;
- ограничить доступ к MinIO/PostgreSQL/Redis;
- включить резервные копии и регулярно проверять восстановление;
- добавить DDoS/WAF и внешний rate limiting;
- подключить антивирус и media sandbox;
- провести pentest и криптографический аудит.


## Запуск пользовательского кода

JavaScript web-preview работает в iframe без `allow-same-origin`, с `connect-src 'none'` и без доступа к cookies, localStorage и токенам основного приложения. Python, Java и консольный JavaScript запускаются отдельным Runner.

В Docker Runner не имеет сетевого интерфейса и соединяется с Core только Unix socket. Корневая файловая система read-only, рабочие каталоги одноразовые, а пользовательский код выполняется под отдельным непривилегированным UID. Применяются ограничения CPU, памяти, PID, времени, файлов и вывода. Runner не получает базу, ключи сообщений и пользовательские токены.

Контейнерная изоляция снижает риск, но не является абсолютной защитой от уязвимости ядра или runtime. Для запуска кода полностью недоверенной массовой аудитории нужны отдельные worker-хосты или microVM, seccomp/AppArmor, очереди, квоты, мониторинг и pentest. Локальный process-режим нельзя выставлять в интернет.
