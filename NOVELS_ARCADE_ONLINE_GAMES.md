# НЕМАКС PLAY: новеллы, аркада и онлайн-столы

Этот документ описывает новые игровые модули проекта.

## 1. Конструктор игр-новелл

Откройте **Игры → Конструктор** и выберите тип **«Игра-новелла»**.

Новелла хранится как обычный публикуемый игровой проект. Автор может:

- создать до 120 сцен;
- назначить стартовую сцену;
- задать название сцены, говорящего персонажа и текст;
- использовать emoji-персонажа;
- указать фон цветом, CSS-gradient или URL изображения;
- добавить до 12 вариантов выбора на сцену;
- связать каждый выбор с другой сценой;
- завершить историю выбором без следующей сцены;
- начислять или вычитать сюжетные очки;
- тестировать проект до публикации;
- публиковать и снимать его с публикации;
- получать статистику запусков и результаты игроков.

Backend нормализует проект: ограничивает размер текста, количество сцен и вариантов, удаляет переходы к отсутствующим сценам и гарантирует существование стартовой сцены.

## 2. Тетрис и змейка

Вкладка **«Аркада»** содержит две встроенные игры.

### Тетрис

Управление на ПК:

- `←` и `→` — перемещение;
- `↑` — поворот;
- `↓` — ускоренное падение;
- `Space` — мгновенный сброс;
- `P` — пауза.

На телефоне под доской отображаются сенсорные кнопки. Счёт зависит от количества одновременно удалённых линий.

### Змейка

Управление:

- стрелки или `WASD`;
- `P` — пауза;
- сенсорная крестовина на мобильном устройстве.

Лучший результат каждого пользователя попадает в общую таблицу лидеров. Сервер принимает только целое неотрицательное значение в ограниченном диапазоне.

## 3. Отдельный игровой сервер

Шахматы, шашки, аркадные рекорды и покерные столы вынесены из Core API в отдельный **Game Server**:

```text
Game Server: http://localhost:3004
Публичный API через Vite/Nginx: /game-api
Локальная игровая база: server/data/game-db.json
```

В production игровой сервис использует отдельное подключение `GAME_DATABASE_URL`, а авторизацию проверяет через защищённый внутренний маршрут Core API. Игровой процесс не получает ключи сообщений и не записывает состояние партий в основную базу мессенджера.

## 4. Полные онлайн-шахматы

Реализованы:

- белые и чёрные, зрители и новая партия;
- проверка всех ходов только на Game Server;
- шах, мат и пат;
- короткая и длинная рокировка;
- запрет рокировки из-под шаха, через битую клетку или после хода короля/ладьи;
- взятие на проходе только на непосредственно следующем ходу;
- превращение пешки с выбором ферзя, ладьи, слона или коня;
- правило 50 ходов;
- троекратное повторение позиции;
- ничья при недостатке материала;
- история и подсветка последнего хода;
- автоматическая победа оставшегося игрока при выходе соперника.

## 5. Русские шашки

Движок следует основной логике русских шашек:

- простые шашки ходят вперёд, но бьют вперёд и назад;
- взятие обязательно;
- при наличии продолжения боя ход продолжается той же шашкой;
- дамка ходит на любое количество свободных диагональных клеток;
- дамка может перепрыгнуть фигуру соперника и приземлиться на любой свободной клетке за ней;
- шашка, достигшая последней горизонтали во время боя, сразу становится дамкой и продолжает взятие как дамка;
- партия заканчивается при отсутствии фигур или допустимых ходов;
- предусмотрена ничья после длительной серии ходов дамками без взятий.

## 6. Texas Hold’em на условные фишки

Покер существует исключительно как социальная игра на **условные фишки**. Фишки нельзя купить, продать, обменять, подарить за деньги или вывести. Денежные призы и реальные ставки отсутствуют.

### Ежедневный вход

После успешного входа в НЕМАКС frontend обращается к игровому кошельку. При первом входе в новый день по UTC кошелёк получает:

```text
5000 условных фишек
```

Повторное открытие в тот же день бонус не начисляет.

### Турниры

Размеры:

```text
3, 8, 16, 50 или 100 игроков
```

Скорости:

```text
обычный / турбо
```

Бай-ины:

```text
50, 100, 500, 1000, 5000 или 10000 условных фишек
```

Доступны все 60 сочетаний. Турнир запускается после заполнения. Игроки начинают с 10 000 турнирных фишек. При вместимости больше восьми создаются несколько внутренних столов; между синхронизированными раздачами сервер перераспределяет игроков. Блайнды растут по расписанию: обычный уровень длится 5 минут, турбо — 2 минуты. Призовой фонд формируется только из игровых бай-инов и распределяется в условных фишках, без комиссии и денежной стоимости.

### Кэш-столы

Доступны блайнды:

```text
50/100
100/200
250/500
500/1000
1000/2000
2500/5000
```

За одним столом до восьми игроков. Вход — от 20 до 100 больших блайндов. Оставшийся стек возвращается в условный кошелёк при выходе. Докупка разрешена между раздачами в пределах максимального стека.

### Правила раздачи

Сервер выполняет и проверяет:

- случайную криптографическую перетасовку колоды;
- дилера, малый и большой блайнд;
- preflop, flop, turn, river и showdown;
- `fold`, `check`, `call`, `bet`, `raise`, `all-in`;
- минимальный рейз и сумму к коллу;
- основные и боковые банки;
- деление банка при равных комбинациях;
- лучшую комбинацию из пяти карт среди семи;
- таймер действия и автоматический check/fold;
- сокрытие закрытых карт других игроков до вскрытия.

## 7. Game API

```text
GET    /game-api/wallet

GET    /game-api/arcade/leaderboard?game=snake|tetris
POST   /game-api/arcade/score

GET    /game-api/boards
POST   /game-api/boards
GET    /game-api/boards/:id
DELETE /game-api/boards/:id
POST   /game-api/boards/:id/join
POST   /game-api/boards/:id/leave
POST   /game-api/boards/:id/action

GET    /game-api/poker/catalog
POST   /game-api/poker/tournaments/join
POST   /game-api/poker/tournaments/:id/leave
POST   /game-api/poker/cash/join
GET    /game-api/poker/games/:id
POST   /game-api/poker/games/:id/action
POST   /game-api/poker/games/:id/leave
POST   /game-api/poker/games/:id/rebuy
```

Старые маршруты `/api/game-tables` и `/api/arcade` возвращают `410 Gone`, чтобы клиент не смешивал Core API и игровой сервис.

## 8. Запуск и проверка

Обычный запуск поднимает Game Server автоматически:

```bash
npm run dev
```

Отдельно:

```bash
npm run server:games
```

Проверка движка:

```bash
npm run test:games
```

Полный набор self-tests:

```bash
npm run check
```

Тесты проверяют рокировку, взятие на проходе, превращение, летающую дамку, взятие назад, ежедневные фишки, 3- и 16-местные турниры, разбиение на несколько столов, скрытие чужих карт, кэш 50/100 и вычисление комбинаций.

Подробная архитектура вынесенного сервиса: [`GAME_SERVER_CHESS_CHECKERS_POKER.md`](./GAME_SERVER_CHESS_CHECKERS_POKER.md).
