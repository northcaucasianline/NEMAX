# НЕМАКС Game Server: шахматы, русские шашки и покер на условные фишки

## 1. Назначение сервиса

Игровая логика отделена от основного backend мессенджера и работает отдельным процессом:

```text
Frontend              http://localhost:5173
Core API              http://localhost:3001
Realtime / Worker     http://localhost:3002
Code Runner           http://localhost:3003
Game Server           http://localhost:3004
Game API              /game-api
```

Game Server отвечает за:

- серверное состояние шахматных и шашечных столов;
- проверку допустимости каждого хода;
- игровые кошельки с условными фишками;
- турнирные и кэш-столы Texas Hold’em;
- колоды, закрытые карты, очередность действий, банки и результаты;
- серверные таймеры действий;
- аркадные таблицы лидеров;
- отправку игровых событий через Realtime-сервис.

Core API остаётся владельцем аккаунтов и сессий. Game Server не получает пароли, refresh-токены, ключи сообщений или содержимое переписки. Он передаёт access-токен на закрытый внутренний маршрут Core API и получает только безопасный профиль авторизованного пользователя.

## 2. Хранилище

### Локальный режим

```text
server/data/game-db.json
```

Игровая база отделена от основной базы:

```text
server/data/db.json
```

### Production

Можно задать отдельное подключение PostgreSQL:

```env
GAME_DATABASE_URL=postgres://nemax:password@postgres:5432/nemax
```

Состояние записывается в таблицу `game_server_state`. Для крупного публичного проекта эту JSON-модель следует далее нормализовать по таблицам турниров, раздач, мест, кошельков и действий.

## 3. Взаимодействие сервисов

Game Server использует:

```env
CORE_INTERNAL_URL=http://127.0.0.1:3001
REALTIME_INTERNAL_URL=http://127.0.0.1:3002
INTERNAL_SERVICE_SECRET=длинный-секрет
```

Внутренние запросы подписываются заголовком `X-Internal-Service-Secret`. Nginx публикует только `/game-api`; внутренние маршруты между сервисами наружу не выводятся.

После изменения стола Game Server отправляет участникам событие через Realtime. Клиент повторно читает актуальное состояние с Game API, поэтому сервер остаётся единственным источником истины.

## 4. Шахматы

Реализована серверная доска 8 × 8 со следующими правилами:

- движение пешки, коня, слона, ладьи, ферзя и короля;
- запрет хода на занятую своей фигурой клетку;
- запрет взятия короля как обычной фигуры;
- запрет оставлять собственного короля под шахом;
- определение шаха, мата и пата;
- короткая рокировка;
- длинная рокировка;
- запрет рокировки, если король или нужная ладья уже ходили;
- запрет рокировки при отсутствии ладьи;
- запрет рокировки через занятые или атакованные клетки;
- запрет рокировки из положения шаха;
- взятие на проходе только сразу после двойного хода соседней пешки;
- выбор фигуры при превращении: ферзь, ладья, слон или конь;
- правило 50 ходов;
- троекратное повторение позиции;
- ничья при недостатке материала;
- история ходов;
- победа оставшегося игрока при выходе соперника.

Все проверки выполняются на Game Server. Переданное клиентом новое состояние доски игнорируется: клиент отправляет только начальную и конечную клетку и, при необходимости, выбранную фигуру превращения.

## 5. Русские шашки

Реализованы основные правила русских шашек:

- простая шашка ходит на одну диагональную клетку вперёд;
- простая шашка бьёт и вперёд, и назад;
- при наличии взятия обычный ход запрещён;
- серия взятий выполняется одной и той же фигурой;
- дамка ходит по диагонали на любое количество свободных клеток;
- дамка перепрыгивает одну чужую фигуру и может приземлиться на любую свободную клетку за ней;
- после приземления сервер проверяет продолжение боя;
- простая шашка, достигшая последней горизонтали во время боя, сразу становится дамкой и продолжает бой как дамка;
- победа определяется отсутствием фигур или допустимых ходов у соперника;
- предусмотрена серверная ничья после 30 тихих ходов дамками без взятий.

## 6. Условные фишки

Покерная часть является бесплатной социальной игрой. Условные фишки:

- нельзя купить;
- нельзя продать;
- нельзя обменять на деньги или товары;
- нельзя вывести;
- нельзя перевести через платёжный API;
- не имеют денежной стоимости.

В проекте отсутствуют маршруты пополнения, эквайринга и вывода.

### Ежедневный бонус

После успешного входа frontend неблокирующе обращается к Game Server. При первом таком входе пользователя в новый UTC-день сервер начисляет:

```text
5000 условных фишек
```

Сервер хранит `lastDailyBonusDay`, поэтому повторная загрузка страницы или вход с другого устройства в тот же день не начисляет бонус повторно.

## 7. Турниры

### Вместимость

```text
3
8
16
50
100 игроков
```

### Скорость

```text
normal — обычный
 turbo — турбо
```

### Бай-ины

```text
50
100
500
1000
5000
10000 условных фишек
```

Каталог формирует 60 фиксированных сочетаний. Регистрация завершается автоматически при заполнении турнира.

### Стартовый стек и блайнды

Каждый участник получает 10 000 турнирных фишек. Это стек внутри турнира: он отделён от игрового кошелька.

- обычный уровень блайндов: 5 минут;
- турбо-уровень: 2 минуты;
- Game Server пересчитывает текущий уровень по серверному времени;
- длительность хода: 30 секунд в обычном турнире и 15 секунд в турбо;
- при истечении времени выполняется `check`, если он бесплатный, иначе `fold`.

### Многостоловая игра

На одном внутреннем столе размещается до восьми участников. Поэтому:

- турнир на 16 игроков создаёт два стола;
- турнир на 50 игроков создаёт семь столов;
- турнир на 100 игроков создаёт тринадцать столов.

Между завершёнными раздачами сервер удаляет выбывших и балансирует рассадку. Новая синхронизированная раздача запускается после обработки всех столов текущего цикла.

### Призы

Призовой фонд равен сумме турнирных бай-инов. Рейк отсутствует. Выплаты начисляются только в условных фишках. Количество призовых мест рассчитывается примерно для верхних 15% участников, после чего фонд распределяется по весам мест.

## 8. Кэш-столы

Фиксированные блайнды:

```text
50/100
100/200
250/500
500/1000
1000/2000
2500/5000
```

Правила:

- до восьми игроков;
- минимальный вход — 20 больших блайндов;
- максимальный вход — 100 больших блайндов;
- бай-ин списывается из условного кошелька;
- остаток стека возвращается в кошелёк после выхода;
- во время активной раздачи выход переводится в `fold`, возврат выполняется после её завершения;
- докупка разрешена между раздачами до максимального стека.

## 9. Texas Hold’em

Game Server реализует:

- криптографическое перемешивание 52-карточной колоды через `node:crypto.randomInt`;
- две закрытые карты;
- dealer button, small blind и big blind;
- preflop, flop, turn, river и showdown;
- действия `fold`, `check`, `call`, `bet`, `raise`, `all-in`;
- размер к коллу;
- минимальный размер повышения;
- ограничение действия доступным стеком;
- основных и боковых банков;
- деление банка при ничьей;
- оценку лучшей пятикарточной комбинации из семи карт;
- старшую карту, пару, две пары, тройку, стрит, флеш, фулл-хаус, каре, стрит-флеш и роял-флеш;
- серверные таймеры действий;
- автоматический check/fold при тайм-ауте;
- скрытие чужих закрытых карт до вскрытия;
- сокрытие полной колоды из каждого публичного ответа API.

Клиент не получает колоду и не определяет победителя. Даже при изменении frontend-кода результат формирует Game Server.

## 10. API

Все маршруты требуют bearer access-токен, кроме `/health` и `/metrics`.

### Кошелёк

```text
GET /game-api/wallet
```

### Аркада

```text
GET  /game-api/arcade/leaderboard?game=snake|tetris
POST /game-api/arcade/score
```

### Шахматы и шашки

```text
GET    /game-api/boards
POST   /game-api/boards
GET    /game-api/boards/:id
DELETE /game-api/boards/:id
POST   /game-api/boards/:id/join
POST   /game-api/boards/:id/leave
POST   /game-api/boards/:id/action
```

### Покер

```text
GET  /game-api/poker/catalog
POST /game-api/poker/tournaments/join
POST /game-api/poker/tournaments/:id/leave
POST /game-api/poker/cash/join
GET  /game-api/poker/games/:id
POST /game-api/poker/games/:id/action
POST /game-api/poker/games/:id/leave
POST /game-api/poker/games/:id/rebuy
```

## 11. Локальный запуск

Все сервисы:

```bash
npm install
npm run dev
```

Только игровой сервер:

```bash
npm run server:games
```

По умолчанию он слушает:

```text
http://localhost:3004
```

Frontend отправляет запросы на `/game-api`, а Vite проксирует их на порт 3004.

## 12. Docker

```bash
cp .env.example .env
docker compose up --build -d
```

В Compose сервис называется `games`. Наружу он не обязан публиковать порт: Nginx проксирует `/game-api/` во внутреннюю Docker-сеть.

Проверка:

```bash
curl http://localhost/game-api/wallet \
  -H "Authorization: Bearer ACCESS_TOKEN"
```

## 13. Тестирование

```bash
npm run test:games
```

Проверяются:

- рокировка;
- взятие на проходе;
- превращение пешки;
- дальнее взятие дамкой;
- взятие назад простой шашкой;
- ежедневный баланс;
- полный каталог 60 турниров;
- турнир на три игрока;
- турнир на 16 игроков и два стола;
- скрытие чужих карт;
- кэш-стол 50/100;
- вычисление роял-флеша.

Все локальные self-tests:

```bash
npm run check
```

## 14. Production-заметки

Перед публичным запуском рекомендуется:

- использовать отдельную PostgreSQL-базу или отдельную схему для Game Server;
- запускать несколько игровых узлов только после добавления распределённой блокировки состояния;
- хранить турнирные действия и раздачи в нормализованных таблицах;
- добавить повторяемый журнал действий для разбора спорных партий;
- подключить наблюдаемость, алерты и нагрузочное тестирование;
- не добавлять конвертацию условных фишек в деньги или приобретаемые предметы без отдельной правовой и возрастной экспертизы.
