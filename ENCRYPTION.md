# Шифрование

Проект поддерживает два уровня защиты.

## 1. Шифрование на сервере

- AES-256-GCM;
- ключ генерируется `crypto.randomBytes(32)`;
- новый ключ каждые пять минут;
- отдельный случайный 96-битный IV для каждого сообщения и объекта;
- GCM authentication tag защищает целостность;
- старые ключи сохраняются для истории;
- текст и вложения хранятся зашифрованными;
- ключи находятся только у Core API, Worker их не получает.

Кольцо ключей хранится в `server/data/message-keys.json`. Его необходимо резервировать вместе с базой и объектным хранилищем.

## 2. Секретный server-blind режим

Клиент создаёт ключ устройства P-256 ECDH. Для сообщения генерируется случайный AES-GCM content key, который отдельно оборачивается для устройств участников через ephemeral ECDH. Сервер сохраняет только ciphertext, IV, ephemeral public key и recipient envelopes.

Секретный режим включается обоими участниками личного чата. Текст расшифровывается на клиенте.

## Граница безопасности

Серверное AES-шифрование защищает данные на диске, но Core может их открыть. Секретный режим скрывает текст от Core, однако текущая реализация не является прошедшей аудит реализацией Signal Double Ratchet/MLS: отсутствуют полноценные one-time prekeys, ratchet каждого сообщения, key transparency и формальная проверка протокола.

Для production обязательны HTTPS/WSS, безопасное хранение приватного ключа устройства, резервные копии ключей Core и независимый аудит.
